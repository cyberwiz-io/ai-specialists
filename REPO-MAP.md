# Repository map

Start here. Find the smallest set of files for your task and read only those. The shipped product is materials-only instructions; nothing here runs against a user's systems.

## Route by task

| I want to... | Read |
| --- | --- |
| Find a specialist for a job | `python3 -B scripts/pack.py find <words>`, or the table for its family below |
| Read or edit one specialist | `catalog/<family>/<slug>.md` (one card, about 2 KB) |
| Add a specialist | [Card guide](docs/CARD-GUIDE.md); add the role to `catalog/families.json`; write `catalog/<family>/<slug>.md`; then run the three commands under Rules |
| Change shared behavior or boundaries | [Marketing coordinator](pack/COORDINATOR.md) (marketing only) or [family coordinator](pack/FAMILY-COORDINATOR.md) (every other family). Guarded by `scripts/packlib/check.py` (versions, freshness) and `tests/test_pack.py` |
| Change the marketing campaign flow | [Marketing workflow](pack/MARKETING-WORKFLOW.md) |
| Change user setup text | [Start here](pack/START-HERE.md) |
| Change build, checks or tests | [Contributing](CONTRIBUTING.md), then `scripts/packlib/` (`cards.py` card rules, `check.py` checks, `build.py` outputs) and `tests/`; finish with the three commands under Rules |
| Install a specialist family without pasting | [Install guide](docs/INSTALL.md); `.claude-plugin/marketplace.json` and `plugins/<family>/` are generated by `scripts/packlib/plugin.py` |
| Run or extend the card evaluations | [Evals](evals/README.md), `evals/fixtures/<family>.json`, `scripts/evals.py`; Claude Code uses `.claude/skills/card-evals/SKILL.md` |
| Understand ownership of files | `config/module-map.json` (modules, guides, interfaces, digests) |
| Check scope, limits and status | [Roadmap](docs/ROADMAP.md), [Validation](docs/VALIDATION.md) |

## Layout

| Path | Contents | Edit by hand? |
| --- | --- | --- |
| `catalog/<family>/<slug>.md` | One role card each | Yes |
| `catalog/families.json` | Roster: families, roles, slugs, sensitivity | Yes |
| `catalog/<family>/INDEX.md` | Family index | No, generated |
| `catalog/REGISTRY.jsonl` | One line per specialist; grep it | No, generated |
| `pack/*.md` | Coordinators, workflow, templates, start guide | Yes, except `STARTER-PACK.md` |
| `pack/STARTER-PACK.md` | Marketing starter, pasted as one file | No, generated |
| `dist/packs/<pack>.md` | Pasteable combined pack per family, or per part where `families.json` lists `packs` | No, generated |
| `work/release/*.zip` | Release archive and one upload-ready skill ZIP per family from `pack.py release`; CI attaches them to tagged GitHub Releases | No, generated and never committed |
| `.claude-plugin/marketplace.json`, `plugins/<family>/` | Claude Code marketplace and one plugin per family: `skills/<family>/SKILL.md` with the cards in `references/`, a read-only subagent per card, and a `<family>-orchestrator` in `agents/` | No, generated |
| `docs/INSTALL.md`, `evals/` | Install paths, their status and limits | Yes |
| `.claude/` | Maintainer config for Claude Code: hook, commands, card reviewer | Yes |
| `config/modules.json` | Module definitions | Yes |
| `config/module-map.json` | Module map with digests | No, generated |
| `docs/` | Guides, roadmap, validation status | Yes |
| `evals/fixtures/<family>.json` | Fictional evaluation tasks, at least one per card | Yes |
| `evals/reports/` | Reviewed evaluation reports | Yes, after review |
| `.claude/` | Claude Code skill and subagents for the evaluation harness; not shipped | Yes |
| `work/evals/<run>/` | Prompts, replies, grades and report of one run | No, generated and never committed |
| `scripts/`, `tests/` | Build, check, search; their tests | Yes |
| `LICENSES/`, `NOTICE.md`, `LICENSE.md` | License text and coverage | Rarely |

Skip `dist/`, `work/` and `LICENSES/` when exploring: they are generated copies or license text.

## Rules that apply everywhere

- Materials only. No role enables an external action or promises a capability the host does not provide.
- Fictional examples only. No credentials, private profiles, customer data or generated campaign records.
- After any change run `python3 -B scripts/pack.py build`, then `python3 -B scripts/pack.py check` and `python3 -B -m unittest discover -s tests`.
